## 👔 CTO — architecture, scalability, technical debt

**Strengths**
- Clean separation between Next.js client + Python sidecar. The two-tier LLM cache (PR-3) is a model for how every expensive computation should live in this codebase.
- Component primitives (`TwoColumnTabGrid`, `TabSection`, `TabLoadingSkeleton`, `Toast`) compose cleanly. New tabs are ~50 lines each rather than 200.
- `lib/db/` is parameterized, schema-versioned, idempotent. Zod schemas across every module make schema drift a runtime error rather than silent data loss. Migration safety is real.
- `Cache-Control: private, no-store` on all auth-gated data routes closes a real PII leak vector that production previously had.

**Risks**
- **Per-Lambda rate limit** ([`lib/rate-limit.ts`](../lib/rate-limit.ts)) — at scale, distinct invocations share no state. Documented; not yet wired to Upstash Redis (`D7` in BACKLOG). One incident-trigger condition: a small attacker who can keep N Lambdas warm bypasses the limiter.
- **No DB migration log**. `lib/db/client.ts` uses try/catch ALTER blocks via the `migrate()` helper. Works, but no way to know which version a production DB is currently at. (T8 in BACKLOG.)
- **Sidecar is a single point of failure**. `fetchWithRetry` recovers transient 5xx, but a sustained sidecar outage cascades to 502s on every reading route. No circuit-breaker.
- **`force-dynamic` everywhere on auth-gated pages** is correct, but means every dashboard view is a Lambda invocation. The Compare tab fetches compatibility on every visit. The Compatibility API has its own DB cache, so cost is bounded — but `db.compatibility.list(userId)` runs on every dashboard navigation. Move that fetch into the Compare-tab effect (lazy).
- **Two profile-form codepaths still coexist**: `ProfileForm.tsx` (mobile edit `/profiles/[id]/edit`) and `ProfileFormFields.tsx` (sidebar). The next mobile-edit-as-sheet refactor closes it.

**Next-quarter calls**
1. Adopt Upstash Redis for rate limit (one env var, drop-in swap).
2. Stand up a `schema_migrations` table; back-fill the current version.
3. Sidecar circuit-breaker on top of `fetchWithRetry`.
4. Observability: Vercel Analytics is in place, but no error aggregation (Sentry/Rollbar). For a paid product, this is below the threshold.

## 🧑‍💻 Senior Engineer — code quality, test coverage, edge cases

**Strengths**
- 347 tests, all green. The LLM cache tier-routing in PR-3 has surgical tests (regenerate-only-current vs. regenerate-only-natal). Zod schemas mean schema-drift bugs surface immediately at runtime.
- Display rules (`lib/display.ts`) are tested. The toast system is tested.
- `getUserId(session)` helper killed 15 sites of `(session.user as { id: string }).id` casts.
- Pre-push hook (`.githooks/pre-push`) runs `tsc --noEmit` + `vitest run` — contributors can't push a broken tree.

**Smells**
- **`lib/typography.ts`** is still a 217-line module with mixed concerns (font tokens, scale, glass surface, motion). The deprecation comment is there; pruning is opportunistic. Worth scheduling a cleanup once two or three more callers migrate to `.ac-*` classes.
- **No tests for `ProfileForm.tsx`** (mobile edit fallback) despite holding real form validation. If that route ever goes prod-broken, no test catches it.
- **`ProfileSidebar.tsx`'s `window.location.href` on save** forces a full reload. The toast fires *before* the navigation, so on a slow link the user may not see it. A `router.refresh()` + manual chart re-fetch would feel snappier — but that's a non-trivial refactor.
- **No integration tests for the compare → AI-insight flow.** The route is tested in isolation; the user journey isn't.

**Low-hanging fruit**
1. Convert `ProfileForm.tsx` mobile edit to a sheet that uses `ProfileFormFields` — kills the two-codepath divergence.
2. Add a "compare tab end-to-end" test that mounts the dashboard with two profiles + clicks through compare.
3. Add per-route OpenAPI/JSON-Schema docs (lightweight) — current `docs/api.md` is hand-maintained.

## 🔍 Tester — untested paths, integration gaps, UX edge cases

**Untested journeys to write next**
1. **First-time user.** Sign in via Google → land on dashboard → sidebar prompts create form → fill bad date (1899) → form should reject → fix → submit → loading screen → dashboard with Today reading.
2. **Profile delete → re-create with same name.** Does the readings cache from the old profile leak in? (Unlikely — readings are keyed by profile_id — but worth a fixture test.)
3. **Admin edits LLM custom_instructions** in Settings → user visits Today → reading should regenerate (PR-3 fingerprint). Currently only unit-tested at the route level; no end-to-end check.
4. **Sade Sati alert** shows correctly when transit data has it. The Today tab uses `generateInsights()` which depends on `transitOutput` — if transit is loading, the insights look empty. Now that Today's empty section is hidden (PR-2), this could mask the alert. Worth a fixture.
5. **`?create=1` URL** on a user with the 10-profile max. The sidebar form will show but the POST will 403. UX should surface this clearly — right now the inline error is small.

**UX edge cases to manual-test**
- **Long names** (e.g. 60-character full names) in profile chips, sidebar header, Ask panel context — `formatName` doesn't truncate. The chips have `whitespace-nowrap` so will overflow horizontally. Add `truncate` + a max-width.
- **Birth time `00:00`** — does the chart engine handle midnight births correctly? The form allows it.
- **Profile with no relationship/gender** — sidebar meta line conditionally renders; verify visual on an "Other / unset" profile.
- **Compatibility check between two same-gender profiles** — `filterCandidates` returns empty, so the dropdown is empty. The "Add partner profile" CTA shows. Verify the link still routes correctly (`/dashboard?create=1`).

**Reproducibility gaps**
- We have no seed-data fixture for "common profile shapes." Every test stubs different shapes. A `tests/fixtures/profiles.ts` would deduplicate ~50 lines across test files.

## 🎯 Product Manager — feature gaps, user journey friction

**What works well**
- Sidebar create flow is now zero-friction (PR-1). Empty users land directly on it.
- The two-tier LLM strategy positions you to ship "weekly horoscope" or "monthly outlook" without re-architecting the cache.
- Admin draft assistant (in the Questions tab) is a real workflow accelerator — saves the practitioner real time per consultation.

**Friction surfaces to test with users**
1. **Discoverability of the Compare tab.** It's a tab inside a profile. A new user might not realise compatibility is per-pair. Consider a "Compare with another profile" affordance in the sidebar.
2. **No "share my chart" affordance.** D5 in BACKLOG, but as the product matures, the absence of any social sharing is a growth ceiling. Even a "download as PDF" feels like a missing primitive.
3. **The Ask panel doesn't show prior questions.** A returning user who asked a question last week has no history. The admin can see it; the user can't. That's a credibility / trust gap.
4. **No notification on consultation answered.** Per BACKLOG (D3 variant). The user has to come back and check. Email or in-app banner.
5. **Today tab on a profile with no shifts** is now correctly hidden (PR-2). But it leaves the screen feeling thin for a casual visitor. Consider showing **upcoming** shifts (next pratyantar) even if there's no current alert.
6. **No "tour" or empty-state guidance.** New users see all 10 tabs immediately; the cognitive load is real. A subtle "Start with Today" anchor for first-visit users would lower the barrier.
7. **`isAdmin` toggles things invisibly.** A user has no way to know what they're missing. If you ever want admin features to be a paid tier, the gate becomes a positioning feature, not a hidden flag.

**Product-mechanics gaps**
- The **`relationship` field** is fixed to a list (Self / Spouse / …). For Indian context, things like "Father-in-law", "Cousin" are common. Consider a free-text option.
- **No way to bookmark a transit moment** — "I want to come back to today's chart." Not now-urgent, but interesting for the practitioner audience.
- **Pending-request 409** (added in this audit) prevents multiple in-flight questions — but the error message doesn't link the user to their pending one. Add a "View your pending request" CTA in the 409 response.

## 📣 CMO — positioning, copy, conversion paths, onboarding

**What works**
- The brand wordmark (post-PR-1) reads clearly. "Astro Chaganti" with the italic "Chaganti" in accent is dignified.
- Cosmic landing has a unique aesthetic. The earth globe video is striking.

**What pulls back**
1. **No proposition above the fold on the landing.** `CosmicLanding` shows the brand + likely a CTA, but there's no "Vedic charts by Dr. Vinay Kumar Chaganti — sign in" framing visible from the start. The visitor has to read between visuals.
2. **No social proof.** No testimonials, no credentials line beyond the title. For a practitioner-led product, credentials are conversion. "20+ years of practice", "Author of X", whatever the real claims are.
3. **Pricing is hidden.** The consultation pricing lives in the admin settings — users see fees only when they submit a question. A "Pricing" section on landing OR a small in-app "What this costs" panel helps trust.
4. **Disclaimer is in the sidebar at 50% opacity.** Legally sufficient, but reads as defensive. Consider a separate "How to read this" or "Method" tab that proactively says "this is for reflection, not prediction" — turn a legal hedge into a value statement.
5. **No FAQ / "How accurate is the time?"** Users will ask: do I need exact birth time? Tropical vs. sidereal? Lahiri vs. Raman? The product has strong opinions; making them visible builds credibility.
6. **No "About Dr. Chaganti"** page. Credits page exists but is about the engine. The practitioner is the brand here — make him visible.
7. **No email capture for non-signed-in visitors.** Anyone who lands and isn't ready to sign in with Google leaves with nothing. Even a small "Updates when new features ship" capture would be worth setting up.

**Copy nits**
- "Ask an expert" is generic. "Ask Dr. Chaganti" would be more concrete and resonant. (Trade-off: when you have other experts, this breaks.)
- "Question submitted" — the success state says "An astrologer will review". When you only have one astrologer, "Dr. Chaganti will respond" is warmer.
- The Today reading is now generated content (~2× current period, ~5× natal). Users don't know what's AI vs. authored. Either own the AI part as a feature ("Synthesized from Dr. Chaganti's interpretive library by GPT-class models") or hide the seams more carefully.
